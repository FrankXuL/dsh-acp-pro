# ACP 对齐原生：分层重构、跨来源告知、轨迹与用量对标、清理与 README

> 来源：wayfinder 地图 [`.scratch/acp-native-parity/map.md`](../acp-native-parity/map.md)（7/7 票已关闭）。本规格把地图决策折叠成可实施条目，不新增未拍板的决定。

## Problem Statement

用户在使用 dsh-acp-pro 时遇到四类问题：

1. **仓库不可维护**：`acp-adapter.ts`（1488 行）、`acp-agent.ts`（880 行）、`model-seat.tsx`（577 行）每个文件都混杂了多种互不相关的变化原因。想加一个新能力时，改动点散落在大文件内部若干处，review 困难、回归风险高。
2. **跨来源切换无告知**：在一个会话里从 dsh 原生切到某个 ACP Agent（或 ACP A 切到 ACP B）时，ACP 内部会话会被重建、历史被压平成文本传给新 Agent、对方的工具执行过程对新模型不可见。用户看不到任何提示，以为只是换了个模型。
3. **ACP 会话的可观测性弱于原生**：原生 dsh 有轨迹视图（请求头、回合结构、工具行、usage 面板、TTFT / tok-s），但 ACP 的工具 / 计划 / 权限卡片只出现在 Chat 视图，轨迹里看不到；用户无法像用原生 provider 那样审视 ACP 回合。
4. **仓库资产冗余且许可叙事不一致**：一次性调研产物与截图堆积；`LICENSE` / `NOTICE` 保留了上游派生归属，与仓库三处文档「必须保留归属」的表述互相牵制；README 291 行、含已无用的截图节。

## Solution

四件事按固定顺序交付：

1. **先分层重构（S1–S4）**，把 Host 拆成 `surface → domain → transport`、Client 拆成 `service → view → register`，并加一条静态依赖方向测试防止倒退。重构是纯搬运，行为零变化。
2. **再做跨来源告知**：不禁止切换，但在跨来源选中时用原生审批框说明风险，用户拒绝则保持原选择。
3. **再做轨迹与用量对标**：ACP tool-call 以 `kind: 'node'` 进入原生轨迹视图；用量数据通路零改动，只在三处补「估算」标注。
4. **最后收尾仓库**：清理一次性产物、重写 README 为产品首页。

重构必须先行，因为跨来源告知与轨迹工具行都要动 Client，落在待拆的大文件里之后还要搬一次。

## User Stories

### 分层重构（S1–S4）

1. 作为维护者，我希望 `acp-adapter.ts` 只负责把 domain 语义接到 dsh 契约上，这样我加新能力时不必在一个 1488 行文件里找落点。
2. 作为维护者，我希望回合语义（结果结算优先级、待决标记、未知结果）集中在 `domain/turn.ts` 一处，这样我改取消逻辑时不会碰到注册代码。
3. 作为维护者，我希望绑定与持久化记录集中在 `domain/binding.ts`，这样改存储格式时不会影响会话建立。
4. 作为维护者，我希望 stdio 进程管理与 ACP 协议语义分成两个文件，这样 ACP v2 适配只需要新增协议文件。
5. 作为维护者，我希望 `domain/` 下不出现 `ctx.` 也不 import `surface/`，这样 domain 可以脱离 dsh 宿主单测。
6. 作为维护者，我希望 `client/service/` 不 import react，这样数据决策逻辑能纯函数测试。
7. 作为维护者，我希望 `model-seat.tsx` 拆成 rail / search / list / panel 四个文件，这样改搜索行为不会波及键盘导航。
8. 作为维护者，我希望每个重构切片独立提交、独立回滚，这样出问题时能只回退一片。
9. 作为维护者，我希望有一条测试在有人反向 import 时立刻失败，这样分层不会随时间腐化。
10. 作为维护者，我希望重构后单文件不超过 400 行，这样 review 单个文件时仍能建立完整心智模型。
11. 作为使用者，我希望重构前后 ACP 对话、工具卡、取消、超时行为完全一致，这样我不必为内部整理承担风险。
12. 作为维护者，我希望重构不改变任何对外契约（`plugin:acp/*` 记录名、`acpSessionControl` 服务名、包名、bundle id），这样已安装的用户不需要重新配置。

### 跨来源告知

13. 作为用户，我希望在同一来源内换模型或换推理等级时完全不被打扰，这样日常切换是顺滑的。
14. 作为用户，我希望从 dsh 原生切到 ACP 或从 ACP 切到另一个 ACP 时，先看到一次明确的风险说明，这样我不会在不知情的情况下丢失 ACP 内部会话。
15. 作为用户，我希望这个确认框说明三件事：内部会话会重建、历史将以文本形式传入、对方的工具执行过程不会进入新模型上下文。
16. 作为用户，我希望在确认框里选择「保持当前来源」时，选择完全不变，这样拒绝操作是零副作用的。
17. 作为用户，我希望同一个会话里同一个「来源对」只被问一次，这样反复来回切换不会反复打断我。
18. 作为用户，我希望从 `/model` 弹窗切换时也能被捕获并提示，这样绕行路径不会静默丢失上下文。
19. 作为用户，我希望在会话权限预设为「完全权限」时不会因为审批框被自动拒绝而「切不动且没有任何提示」，这样极端权限配置下功能仍然可用。
20. 作为用户，我希望在没有审批服务的宿主里跨来源切换不被阻塞，但能看到一条不阻塞的提示，这样降级环境仍可工作。
21. 作为维护者，我希望「自动拒绝」不被当作「用户拒绝」，这样降级路径不会静默失败。
22. 作为用户，我希望提示文案走插件自己的 i18n 命名空间、中英都有，这样与界面其他文案一致。

### 轨迹与用量对标

23. 作为用户，我希望在原生轨迹视图里看到 ACP 的工具调用行，这样审视 ACP 回合的方式与原生 provider 一致。
24. 作为用户，我希望轨迹里的 ACP 工具行明确标注为外部 ACP 记录而不是伪装成原生 tool 卡，这样我不会误以为那是 dsh 发起的调用。
25. 作为用户，我希望轨迹里的 ACP 回合能显示正文与思考块，这样和原生一样能看清模型实际产出了什么。
26. 作为用户，我希望轨迹的 timing 面板显示 TTFT、生成耗时与 tok-s，这样我能判断 ACP Agent 的响应速度。
27. 作为用户，我希望轨迹的 usage 面板显示 input / cached / cacheCreated / output / reasoning 分组，这样我能核对 token 消耗构成。
28. 作为用户，我希望 composer 的 usage pill 在 ACP 会话里正常工作，这样不用切视图就能看到用量。
29. 作为用户，我希望上下文占用指示器在 ACP 会话里仍显示百分比，而不是被隐藏，这样功能不会看起来像坏了。
30. 作为用户，我希望用量数字旁有「按上报增量估算」的说明，这样我知道它不是账单级精确值。
31. 作为用户，我希望上下文占用器的说明提到「窗口大小可能来自 Agent 上报或配置推测」，这样我知道分母可能不准。
32. 作为用户，我希望 plan 与 permission 只在 Chat 视图出现、不被伪装成轨迹里的工具结果，这样记录保持真实。
33. 作为用户，我希望 ACP 侧自己的 system prompt 不被伪造进轨迹请求头，这样轨迹里的请求头反映的是 dsh 侧真实信封。
34. 作为维护者，我希望新增的轨迹 Definition 只读 `plugin:acp/*` 记录、不写任何原生 `tool/call` / `tool/result`，这样不违反仓库的记录真实性约束。
35. 作为维护者，我希望新增 Definition 的 `kind` 与现有三个不同，这样注册不会因重复而抛错。

## Implementation Decisions

### 分层重构（先于所有功能）

- **Host 三层**：`surface`（唯一读宿主服务的适配层，含 adapter、记录生产、session control 桥、插件入口）→ `domain`（纯语义：回合状态机、绑定、能力缓存、transcript、chunk 翻译）→ `transport`（外部进程与 ACP 协议：进程生命周期与 JSON-RPC 会话）。
- **依赖方向铁律**：`surface → domain → transport` 单向，反向 import 禁止；`domain` 不得读取宿主服务上下文。Client 侧对应为 `service`（纯数据决策，不 import react）→ `view`（只呈现）→ `register`（槽位装配）。
- **shared 不扩大**：Host 与 Client 共读的契约层保持现状；不因为分层而往这里加东西，它每加一个字段都是两端兼容成本。
- **四个切片，各自独立可回滚**：S1 抽回合状态机；S2 抽绑定与存储；S3 拆传输层；S4 拆客户端。S1、S2 先行，S3 与 S4 可并行。
- **零逻辑改动约束**：每片提交只移动代码与提取类型，不改任何一行判断逻辑。这是防止 380 行回合状态机引入时序 bug 的唯一护栏。
- **对外契约不变**：记录名、服务名、包名、bundle id 全部不动。
- 结构决策记录在 ADR 中，目标架构图以 JSON 规格形式入库，HTML 为可重现产物不入库。

### 跨来源告知

- **锁的对象是「执行来源 / 模式」**（dsh 原生 / 某个 ACP route），不是模型；同一来源内换模型与推理等级完全不拦。
- **不禁止切换**，只告知与确认。
- **触发时机**：客户端观察到会话级模型目录的 `current` 变化时。这个目录与 `/model` 弹窗共用同一份实例，因此插件无法注入的 `/model` 绕行也能被捕获。
- **形态**：原生审批框，标题表明「切换执行来源」，正文说明三项风险（内部会话重建、历史压平成文本、对方工具过程不可见）。
- **拒绝后**：保持原选择不动，无需回滚（选择尚未提交）。
- **记忆范围**：每个「会话 × 来源对」只问一次。
- **三级降级**：审批服务可用且会询问 → 弹框；无审批服务 → 放行 + 一次性不阻塞提示；审批服务可用但策略为 `never`（如「完全权限」预设）→ 放行 + 提示。**不得**把审批的自动拒绝当作 user 拒绝。
- 文案归插件自己的 i18n 命名空间，中英各一份。

### 轨迹与用量对标

- **轨迹接入方式**：新增声明 `target: 'trajectory'` 的 Conversation Definition，与现有三个 `target: 'chat'` 的 Definition 并存。现有三份未声明排他，因此同一事件可被两条 target 路径各自匹配，无需改 Chat 侧。
- **承载形状**：贡献类型必须是 `kind: 'node'`（这是引擎唯一能把外部对象放进轨迹事件流的通道），节点用「未知表面」兜底形状，`type` 标注为 ACP 来源。不构造原生工具阶段对象，因为那等于伪造 dsh 发起的调用。
- **不注册 view builder**：轨迹 target 的 builder 已由 DSH 自己注册，插件重复注册会抛错。
- **不导入上游内部 helper**：信封只有七个字段的赋值，插件自行内联，避免依赖上游内部实现文件（它不在包的稳定导出面内）。
- **不新增贡献 kind**：贡献类型是封闭联合，插件无法扩展；自造 kind 会被静默丢弃。
- **plan / permission 不进轨迹**：没有对应贡献类型，也没有对应节点类型；硬塞成工具结果会把计划伪装成工具执行，违反记录真实性约束，明确否决。
- **ACP 侧 system prompt 不进轨迹请求头**：伪造系统消息会污染请求头变更计算，否决。
- **usage 数据通路零改动**：ACP 协议里总量 / 输入 / 输出三个字段均为必填，现有「相邻快照差值」实现本就正确；恢复会话无基线时抑制首回合数字的逻辑也正确。
- **只补三处标注**：轨迹 usage 面板底部、composer usage pill 的 tooltip、上下文占用器的 tooltip（仅 ACP 路由会话）。不给每个数字加后缀，不在 Chat 卡片里重复标注。
- **上下文占用器保留百分比**：`usage_update` 上报的是 Agent 自报的窗口大小，不是当前占用；该值作为分母在语义上正确但可能不准。不隐藏功能，改用 tooltip 说明来源与不确定性。

### 清理与 README

- **删除范围**：已闭环任务的一次性调研产物、原型的验证截图、一次性会话交接 prompt、README 不再需要的两张界面截图。
- **保留范围**：描述当前实现的架构文档、长期路线、实机验收证据、插件开发指南、工程技能目录、历史决策档案，以及由工具插件自己维护的 agent 配置 yaml。
- **交叉引用收口**：README 截图节整节移除；架构文档中对截图的引用同批改写，不留死链。
- **README 形态**：八节结构（定位 / 功能 / 架构含文本图 / 安装 / 配置 / 限制 / 开发链接 / 许可证），目标 150 行以内；开发内容并入已有的插件开发指南，不新建第二份开发入口；限制节由平铺改为六组主题。
- **执行顺序**：清理先于 README 重写；README 重写放在最后，与功能落地同批，避免描述立刻过期。

## Testing Decisions

**好测试的判据**：只测外部可观察行为，不测实现细节。重构期间尤其如此——测试在重构前后必须断言不变，否则它锁定的是结构而不是行为。

**复用现有接缝，不新增运行时接缝**（已与用户确认）：

- **L1 真实 cordis + LlmRuntime**（`plugin.test.ts` 已有先例）：用于验证插件注册/卸载、route 过滤、volatile 配置热更新。重构后这些行为必须不变。
- **L2 AcpAdapter + 假宿主 + mock agent 进程**（`adapter.test.ts` 已有先例，最主力）：用于回合语义、取消与超时、usage、记录生产。跨来源告知的宿主侧降级、轨迹记录的可见性都在这层验证。
- **L3 纯函数模块**（chunk 翻译、transcript、permission 分类已有覆盖）：不动，作为回归网。
- **L4 客户端组件测试**（11 个 `client-*.test.tsx`）：用于模型座拆分的回归、跨来源提示的触发、usage 标注文案。

**唯一新增的测试是一个静态检查，不在运行时层**：

- 依赖方向测试：扫描源码，断言 domain 不 import surface/transport、domain 不出现宿主上下文访问、client/service 不 import react、单文件不超过 400 行。这层保护分层不随时间腐化，且不引入任何新的运行时接缝。

**验收门禁**（每片都必须通过）：
- 类型检查退出码 0。
- 全量测试绿，且测试文件数与断言不减少（基线：27 个测试文件 / 204 项测试，2026-10-28 实测）。
- 真机冒烟在全部重构完成后一次性做：一轮 ACP 对话 + 工具卡 + 打开轨迹视图，行为与重构前一致。

**留给实施期实测的验证项**（不能靠推理代替）：
- 轨迹 usage / timing 面板在真实 ACP 回合里确有数值而非占位。
- composer usage pill 与轨迹数值一致。
- 上下文占用器显示的是窗口比例而非 0%。
- 恢复会话且无基线时，首回合显示为「无数据」而非「0」。
- 审批策略为 `never` 时，跨来源确认走的是提示降级而非静默失败。

## Out of Scope

- 修改 DSH 上游（不新增 slot、不改轨迹视图实现、不推上游 PR）。
- 伪造原生 `tool/call` / `tool/result` 会话事件。
- 让 ACP Agent 使用 dsh 自己的工具集。
- `/model` 弹窗内部改造（无法注入）。
- ACP v2 适配（本轮只为它预留 transport 层的落点）。
- 跨设备/跨进程的会话恢复增强、fs/terminal 客户端能力、子会话显示等 roadmap 后续项。

## Further Notes

**上游能力依赖（如实记录，不是本轮可解）**：轨迹里要做到与原生工具卡完全一致，需要上游放宽三处——工具节点的参数类型、贡献类型的扩展点、详情面板的可注入性。本轮只做「诚实但朴素」的工具行。

# 03: 跨来源切换：确认落点、触发时机与降级形态

Type: grilling

Status: resolved

## Question

「跨来源切换」的告知与确认，具体落在哪一层、什么时机触发、用什么文案与形态，才能在覆盖 `/model` 绕行的同时不打扰正常换模型？

## Answer

### 一、定案（用户已拍板）

| 维度 | 定案 |
| --- | --- |
| 是否禁止 | **不禁止**。默认允许跨来源切换。 |
| 触发时机 | **选中那一刻**（客户端 `ModelDirectory.current` 变化），不是下一轮请求时。 |
| 形态 | **原生审批框**（`ctx.approval`），标题写明「切换执行来源」+ 风险说明。 |
| 用户拒绝后 | **保持原选择不动**。选择尚未提交，无需回滚逻辑。 |
| 记忆范围 | **每个「会话 × 来源对」只问一次**（A→B 问过则不再问；A→C 仍要问）。 |

### 二、为什么客户端看得到 `/model` 的绕行（方案可行性的前提）

两条入口共用**同一个** `ModelDirectory` 实例：

- composer 模型位与 `/model` 弹窗都走 `ctx.modelDirectories.directoryFor(sessionId)`（`ui-model-selection/src/client/service.ts:37-90`）；
- 目录数据来自同一 Host RPC `session.modelCatalog()`，随 `llm/adapters-updated` / `settings/document-updated` 刷新（`ui-model-selection/src/client/catalog.ts:47-99`）。

**结论**：即使用户从插件无法注入的 `/model` 弹窗切换，客户端 `current` 也会变，插件**仍能捕获并弹确认**。

### 三、风险的实际内容（审批框文案要说的三件事）

1. **ACP 内部会话会被重建**：`incrementalPrompt()` 在「最新 assistant 消息的 `source.provider` ≠ 当前 route」时返回 `undefined`（`src/host/service/transcript.ts:126-146`），触发 `acp-adapter.ts` 的 `reused && prompt === undefined` 分支，关掉当前 ACP 会话重建。
2. **历史会被压平**：新来源首轮走 `fullPrompt()`（`transcript.ts:180-193`），历史以 `<conversation_history>` 文本形式传入，不是原生状态。
3. **对方的工具执行过程对新模型不可见**：`plugin:acp/*` 记录是 log-only、`ignorable`，不进模型可见历史。

文案（归 `dshAcpPro` locale namespace）：**「切换执行来源」——本会话当前由 {from} 执行。切到 {to} 会重建 {from} 的内部会话，历史将以文本形式传入 {to}；{from} 的工具执行过程不会进入 {to} 的上下文。** 选项：`继续切换` / `保持当前来源`。

### 四、必须处理的降级陷阱（本票最重要的工程约束）

DSH 会话权限预设为「完全权限」时审批策略是 `never`，此时**原生审批框会被自动拒绝**（README「限制」节已记录）。若把确认直接挂在 `ctx.approval` 上，会出现**切不动且无任何提示**的静默失败。

三级降级：

| 宿主条件 | 行为 |
| --- | --- |
| `ctx.approval` 可用且会询问 | 弹原生审批框（主路径） |
| 无审批服务 | **放行** + `conversation.composer.dock` 一次性提示条（不阻塞） |
| 审批服务可用但策略为 `never` | **放行** + dock 提示条。**不得**把自动拒绝当成用户拒绝 |

判定「策略为 never」：调用 `approval.request()` 后检查返回是否**不是用户明确选择**，或读取会话权限预设。**必须在 rc.3 实测该分支**——「自动拒绝」与「用户点拒绝」在返回值上可能不可区分，这是留给实施票的验证项。

### 五、不做的事

- 不做硬锁（用户已明确：无风险就不加限制；有风险则告知而非禁止）。
- 不改 `/model` 弹窗内部（无法注入）。
- 不阻止**同来源**内的模型/推理等级切换（零打扰）。
- 不在会话面板里常驻「当前来源」标识（保留在 Not yet specified）。

### 六、实施票验收点

1. 同来源换模型：**不弹**任何东西。
2. 跨来源（含 `/model` 弹窗触发）：**弹一次**；拒绝后 `current` 保持原值。
3. 同会话同一来源对第二次切换：**不再弹**。
4. 完全权限预设下：**放行 + dock 提示**，不静默失败。
5. 无审批服务的宿主：**放行 + dock 提示**。

定案：不禁止跨来源切换；在客户端捕获 ModelDirectory.current 变化（与 /model 共用同一份目录，故能兜住 /model 绕行），选中时弹原生审批框说明三项风险；用户拒绝则保持原选择；每「会话×来源对」只问一次；审批策略为 never 或无审批服务时降级为放行 + dock 一次性提示，不得把自动拒绝当用户拒绝。

# ACP ecosystem survey — sampled 2026-10-25

Protocol state: **ACP v2** (`agentclientprotocol.com/protocol/v2/*`; docs tree `docs/protocol/v2/` in [agentclientprotocol/agent-client-protocol](https://github.com/agentclientprotocol/agent-client-protocol)). v2 renamed `session/load` → `session/resume` (+ `replayFrom`), added `session/list`, `session/delete`, `session/close`, `state_update` (idle-with-stop-reason even while background work continues), `plan_update` w/ `planId`, elicitation (form/URL), `session_config_options`. Capabilities are grouped into "surfaces" (`session`, `fs`, `terminal`, `mcp`, `auth`, `elicitation`, `subagents`); unknown capability fields MUST be ignored.

Official agent list: **48 agents**, machine-readable at `https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json` ([registry repo](https://github.com/agentclientprotocol/registry)). CI verifies every entry returns valid `authMethods` in the handshake; versions auto-bumped hourly from npm/PyPI/GitHub releases. Schema is distribution-only (`npx` / `uvx` / `binary` with per-platform archive + sha256 + `cmd` + `args`) — **there is no capability matrix**, so a client cannot know feature coverage without probing.

## A — ACP agents (adapters)

- **Claude Agent** — [agentclientprotocol/claude-agent-acp](https://github.com/agentclientprotocol/claude-agent-acp) (was `zed-industries/claude-code-acp`, now org-owned), TypeScript, ~2.7k★, v0.95.0. Launch: `npx @agentclientprotocol/claude-agent-acp`. Coverage: @-mentions, images, tool calls w/ permission requests, TODO lists, custom slash commands, client MCP servers, interactive **and background** terminals, nested **subagent transcripts** (child sessions only when client declares `clientCapabilities.subagents`), session-scoped goals. Quirks: the best parts are gated behind "AIR" extensions under `_meta.jetbrains.air.*` (diff-patch, permission presentation, tool-call contract, session failure, recommended config values) — a generic client silently gets a reduced experience; `/mcp reconnect|enable|disable` is proxied through the SDK control API because Claude Code refuses those commands in SDK mode.
- **Codex** — [agentclientprotocol/codex-acp](https://github.com/agentclientprotocol/codex-acp), TypeScript, ~487★, v2.2.2. Launch: `npx -y @agentclientprotocol/codex-acp` (`CODEX_PATH` to override the bundled binary). Wraps the Codex App Server. Auth: ChatGPT / API key / custom gateway; `NO_BROWSER=1` hides ChatGPT login for remote hosts. Config surfaces: model, reasoning effort, fast mode, approval mode, sandbox mode. Slash commands: `/status /mcp /skills /goal /review /review-branch /review-commit /compact /logout` + configured skills. Emits shell, file-change, MCP-tool, terminal-output, reasoning, plan, web-search, image-gen, **token usage** and review events. Native subagent sessions with a legacy tool-call fallback.
- **Gemini CLI** — [google-gemini/gemini-cli](https://github.com/google-gemini/gemini-cli), TypeScript, ~108k★, v0.65.0. Launch: `npx @google/gemini-cli --acp` (the flag is no longer `--experimental-acp`). Owns its own Google/Vertex auth. Notably **excluded** from `registry-for-jetbrains-air.json`. VS Code path is a separate companion extension (10 recent files, cursor position, ≤16KB selection), not ACP.
- **goose** — [block/goose](https://github.com/block/goose), Rust, ~56k★, v1.56.0. Launch: `goose acp` (subcommand, binary distribution only — no npx). Docs moved to `goose-docs.ai`; `block.github.io/goose/*` now 404s, a live source of stale integration docs.
- **OpenCode** — [anomalyco/opencode](https://github.com/anomalyco/opencode), TypeScript, ~221k★. - **Factory Droid** — `droid@0.249.0`, launch `droid exec --output-format acp-daemon`. ## B — Clients / GUIs and their transcript UX

- **Zed** — [zed-industries/zed](https://github.com/zed-industries/zed), Rust, ~92k★. Already on **ACP v2** (`use agent_client_protocol::schema::v2`). Code worth reading: `crates/agent_ui/src/conversation_view/thread_view.rs` (15,477 lines — the whole transcript), `conversation_view/subagent_card.rs`, `message_queue.rs`, `elicitation.rs`, `thread_search_bar.rs`, plus the `crates/acp_thread` model. Seven tool-call states: `Pending, InProgress, WaitingForConfirmation, Completed, Failed, Rejected, Canceled`. Renderers present: `render_edits_summary`, `render_edited_files(+buttons)`, `render_collapsible_command`, `render_diff_editor`, `render_context_compaction`, `render_elicitation`, `render_acp_subagent_card`, `render_activity_bar`, `render_activity_status_label`, `render_cat_numbered_code_block`. Token/cost meters (`tokens_label`, `cost_label`, `token_usage`, `token_count`) and turn timing (`last_turn_duration`, `turn_time_ms`, `activity_duration`). Permission copy is contextual: "Only this time" / "Always for terminal" / "Always for selected commands"; falls back to "Unknown permission subject". Token-limit callout: "Thread reached the token limit". Subagent card is keyed by **either** a `ToolCallId` or a `MessageId` — the same subagent can appear twice.
- **monoCode** — [hardbeat920/monocode](https://github.com/hardbeat920/monocode), Tauri + React, ~3.4k★. The transcript is `src/features/sessions/ui/AgentTranscript.tsx` — **5,479 lines**. Row taxonomy is the most complete in the ecosystem: `ToolCall`, `ToolCallIcon`, `ToolCallStatusIcon`, `ToolCallSummary`; `ActivityToolRow`, `ActivityThinkingRow`, `ActivityStatusRow`, `ActivityInterjectionRow`, `ActivityNoteRow`; `MonoActivityTrail` + `ActivityPhases` + `PhaseStep` (consecutive calls fold into phases, header via `LiveFoldTitle`); `SubagentStack` / `SubagentRow` / `SubagentPanel`; `ApprovalControls`; `PlanPreview` (Build button with `Building…`/`Built`/`Build` states, `.plan` block status streaming|building|built); `ToolDiffPreview`; `TurnMetricsBadge`; `MonoTurnHeader`; `DaySeparator`; `HandoffDivider`; `CopyTurnButton` / `EditLastTurnButton`. Streaming pacing lives in `src/features/sessions/ui/wordFade.tsx`: `WORD_FADE_MS = 320`, fade adapts to inter-burst cadence clamped `120–400ms` (`cadenceFadeMs = avg*3`), ease `cubic-bezier(0.33,0.53,0.67,1)`, gap cap 1000ms, gated on `prefers-reduced-motion`, kill switch `localStorage["monocode.pacedReveal"]="0"`. Model in `src/features/sessions/model/transcriptActivity.ts`: `TurnItem = block | activity | subagents`, and **subagents are deliberately excluded from the folded trail**. A11y: ~30 `aria-label`, 13 `aria-expanded` (rows are buttons).
- **acp-components** — [zvzuola/acp-components](https://github.com/zvzuola/acp-components), TypeScript/React + framework-agnostic Zustand core, ~65★. Closest thing to a drop-in plugin UI. `packages/react/src/components/chat-view/ToolCallCard.tsx`: `kindIcon` map straight off ACP `ToolKind` (`read, edit, delete, move, search, execute, think, fetch, switch_mode`, fallback `tool`), status dot via `pending|in_progress|completed|failed` classes, whole header is a `<button aria-expanded>`, `LocationChip` renders basename + `:line` as a keyboard-activatable `role="button"` (Enter/Space) linking to the file, body switches on `content` vs `diff` (diff → `DiffView`). `ThoughtView.tsx` and `PlanView.tsx` both auto-expand while streaming and auto-collapse on the streaming→idle transition; PlanView shows `completed/total`, priority classes, spinner while any item is `in_progress`. `StreamingIndicator.tsx` is `role="status"` + 3 dots. Also ships `WorkbenchShell`, diff view, login dialog, command palette, file tree, `SkillView` (`listSkills()`).
- **agent-shell (Emacs)** — [xenodium/agent-shell](https://github.com/xenodium/agent-shell), ~2k★. Native Emacs buffers, no terminal emulation, 23 agents wired. The reference for "editor-native, not a chat box".
- **Neovim** — [CodeCompanion](https://github.com/olimorris/codecompanion.nvim) (~6.9k★, ACP as a chat adapter), [agentic.nvim](https://github.com/carlos-algms/agentic.nvim) (~643★, `acp_providers` table), avante.nvim, hermes.nvim.
- **VS Code** — [formulahendry/vscode-acp](https://github.com/formulahendry/vscode-acp), ACP Patchbay, ACP Pro (also open-vsx for Cursor/Windsurf/Trae), and **Exo** (typography-first, parallel sessions isolated in git worktrees, **native diff-editor approvals**).
- **JetBrains** — built into AI Assistant chat; drives its own registry index + preview channel (`registry-for-jetbrains-preview.json`).

## C — Best-in-class transcript patterns

- **Row anatomy (5 slots)** — kind icon → verb/title → target chip (`basename:line`) → status → disclosure. ACP supplies `kind`, `title`, `status`, `locations[]`, `content[]`. Never trust `title`: agents send vague ones, so monoCode has an explicit `isWeakToolTitle` check and falls back to `composeToolTitle({kind,title,path,query,cwd}) || "Working"`.
- **Status vocabulary** — protocol gives 4 (`pending|in_progress|completed|failed`); Zed renders 7 (adds `WaitingForConfirmation`, `Rejected`, `Canceled`). Collapse provider noise first: monoCode's `isFailedStatus` maps `failed|error|cancelled|canceled` → `rejected`, then `pending|accepted|rejected` (3 visual states).
- **Thinking vs prose** — thought is its own collapsible block, expanded only while streaming, auto-collapsed after (both acp-components and Zed). Without the auto-collapse the transcript becomes unscrollable. monoCode labels it `Thinking…` with a `Shimmer` and an `InitialThinking` state before the first token.
- **Folding** — fold consecutive tool calls into a single activity group (monoCode `ActivityPhases` / `MonoActivityTrail`), but keep **subagents out of the fold** (`TurnItem.subagents`) and never fold a failed or approval-blocked row — monoCode's `toolCallState` returns `pending` for `needsApproval`, which is exactly what keeps the approval row visible.
- **Subagent nesting** — ACP RFD ([subagents](https://agentclientprotocol.com/rfds/subagents)): each subagent is a real child **session id**; parent gets an upsert `subagent_update` (title, description, work state `running|requires_action|idle`) before any child traffic; the launch tool call is *replaced* by `session_message`/`session_message_chunk`; permissions route to the root. Render as a card with its own mini-transcript (Zed `subagent_card.rs`, monoCode `SubagentStack`), deep-linkable, never as a nested scroll region.
- **Plan display** — `plan_update` carries `planId` + `items[{content, priority, status}]`. Render inline as a checklist with an `n/m` counter and per-item spinner (acp-components `PlanView`); monoCode adds an action surface (`Build` → `Building…` → `Built`). Not a modal, not a toast.
- **Permissions** — inline in-stream by default (monoCode `ApprovalControls`, acp-components inline prompt); the spec only demands a modal shape for **elicitation**, where clients MUST identify the agent, let the user edit form answers before sending, offer decline/cancel, and show the target host for URL mode.
- **Diffs** — consume protocol `diff` content, render inside the tool card (`ToolDiffPreview`, `DiffView`) and add one per-turn roll-up row (Zed `render_edits_summary` + `render_edited_files`), which is what makes review feel finished.
- **Errors** — keep the failed row (don't fold), surface the literal error text, and distinguish "unknown" from "failed": Zed has both "Activity unknown" and "Activity unconfirmed" for lost update streams. Truncation must be announced, not silent ("Output was truncated").
- **Usage/cost** — per-turn badge next to the turn header, not a global footer: monoCode `TurnMetricsBadge` + `formatWorkingDuration(elapsed, model)`; Zed `tokens_label`/`cost_label` + `last_turn_duration`. Critical detail: the elapsed timer **pauses** while waiting for approval (`useElapsedFrom(startedAt, paused)`, `waitingForApproval`) — human think-time must not inflate agent speed metrics.
- **Interruptibility & liveness** — `session/cancel` plus v2 `state_update`: foreground idle can coexist with background work, so status must be two-dimensional (foreground turn state + background tasks), and cancelling must leave the partial row intact with an `INTERRUPT_MESSAGE`.
- **Keyboard/a11y** — rows as `<button aria-expanded>`, chips as `role="button"` with Enter/Space, streaming as `role="status"`, decorative motion gated on `prefers-reduced-motion` with an explicit user pref and a localStorage escape hatch (monoCode `pacedRevealPreferred`).

**Implications for the plugin:** (1) probe `initialize` capabilities + first `session/new` `availableCommands`/`configOptions` at connect and build the UI from that, never from a hardcoded agent table; (2) treat subagent sessions, elapsed-pause-on-approval, and plan `n/m` as first-class from day one — retrofitting them into a flat message list is a rewrite; (3) ship the word-level pacing as a *preference*, since half the ecosystem (Zed, agent-shell) deliberately does not animate.

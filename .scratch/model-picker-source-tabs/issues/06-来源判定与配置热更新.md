# 06: 来源判定与配置热更新

Type: research

Status: resolved
## Question

自绘的来源 tab 选择器如何可靠判定来源（DSH 原生 / 每个 ACP），并随配置热更新保持新鲜？

先复用 [`docs/design/dsh-model-picker-research-2026-10-27.md`](../../docs/design/dsh-model-picker-research-2026-10-27.md)（已有结论：`ModelProviderGroup` / `LlmProviderInfo` / 可配置目录都没有 source 字段，组标题只能是 provider `name`）。**它不够用的原因**：没有回答“插件自己的 client 侧如何拿到 ACP 路由清单并与 modelCatalog 对上、配置热更新后如何刷新”，而这正是 tab 分栏的前提。

需要回答（源码契约 + 本仓代码路径）：

1. 插件 client 侧能否直接读到本插件的 `agents` 配置（`ctx.configForms` / `ConfigForm` snapshot / 自有 service / remote descriptor）？读到的是哪一层（profile 列表、displayName、enabled）？
2. `ModelCatalog.groups[].id` 与 ACP 路由（`agents` 的键）是否一一对应；`provider.name` = displayName 的链路确认。
3. DSH 原生 provider 的稳定身份：`deepseek-account`、`deepseek-official` 之外还有哪些（内置/其他插件），客户端能否枚举；无法枚举时的兜底归类策略。
4. 配置热更新链路：设置页保存 / YAML + 重启 / `loader/volatile-update` 分别如何到达 client；选择器组件应订阅什么才能在启用/停用后即时增删 tab。
5. 关闭某 ACP 后：`registerAdapter.replace` → `llm/adapters-updated` → catalog 重拉 → 组消失的端到端链路，以及 `routableProviders` / `modelAvailable` / failures 的表现。
6. 排序：自绘 tab 的顺序应以什么为准（配置键序、注册序、目录序），是否需要在 host 侧显式排序。
7. 若 client 侧拿不到足够信息，host 端最小新增面是什么（例如在本插件自己的 client service 暴露 route 清单），成本与风险。

## Answer

已由 /research 子代理完成，新笔记：[`docs/design/model-picker-source-classification-2026-10-27.md`](../../../docs/design/model-picker-source-classification-2026-10-27.md)（rc.2 源码 + rc.3 逐行复核；未做 GUI 实测）。

**关键结论**
- 来源判定基准 = 本插件配置的路由键集合，从 `ctx.configForms.get(PLUGIN_ID).getSnapshot().value.agents` 读，**零 host 新增面**；`ModelCatalog.groups[].id` 就是 `agents` 键（`prepareRoutes` 强制 `providerInfo().id === route`），`group.name` = `displayName`。
- 原生身份只有 `deepseek-account` / `deepseek-official`；其余无法枚举归属 → 非本插件路由一律归 `DSH` tab（label 写 `DSH`，不写「原生」）。
- `enabled` 必须放进 volatile 的 `agents` dict 内，否则每次保存整插件重挂载；client `snapshotOf/profileOf` 的白名单要同步加。
- 停用若只从 `routes` 过滤，`acp-adapter.sync()` **不会**回收已 spawn 的子进程；停用后组消失、`current` 保留、`routable:false`、设置页行仍 `active:false`。
- 排序：客户端显式稳定排序（`DSH` 第一，ACP 按 `displayName` → `route`）；纯 YAML 键序重排不触发 replace。
- 两条通知（`settings/document-updated` vs `llm/adapters-updated`）不同源：tab 集合以 `groups` 为准。

**待用户拍板（已转 #01/#02）**：停用是否回收子进程；已停用路由上的当前选择是阻止还是回退；tab 排序用固定稳定排序还是允许自定义。

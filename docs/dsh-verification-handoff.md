## 3. 会话配置与恢复

| 场景 | 观察结果 |
| --- | --- |
| 两个模型具有不同 reasoning 选项/默认值 | 原生选择器使用各模型自己的元数据；后续请求使用 Agent 确认值 |
| 同时打开两个 DSH 会话 | 各自的配置、模式和 Agent 会话身份互不串扰 |
| 普通/分组/未知 category 的 select | 已支持的选项可操作；模型和思考强度不出现第二个可编辑入口 |
| 设置失败或 Agent 主动改变配置 | 失败不显示成功，当前值与返回的完整配置快照一致 |
| 生成中调整配置 | 明确显示等待/下一回合应用；停止仍可用 |
| Agent 声明模式或动态命令 | 模式使用实际声明值；命令进入输入区，由用户发送，不假定所有 Agent 都支持 `/compact` |
| 正常结束后重启插件/Agent | 有 load 能力时尝试恢复原身份；无能力时显示新会话语义，不冒充恢复 |
| 恢复后立即切换模型 | 加载与模型切换期间的命令、模式、配置更新不丢失；旧加载配置不覆盖切换返回的新确认值 |
| 请求未确认即断连/超时 | 状态保持未知，不自动增量重提，也不借新会话历史重放间接重提 |
| 明确选择新会话处理未知状态 | 不自动重试旧操作，旧的未确认输入不被再次提交 |

未知结果故障场景优先复用仓库的确定性 fixture 回归证据。真实 Agent 故障验收仅在临时目录使用可观察、可清理的小操作；不要为制造故障终止与本次测试无关的进程。确认取消响应与“未收到任何完成确认”必须分别记录。

## 4. 工具记录与诊断

- 展开工具内容和 diff，检查全部文件位置及行号跳转；键盘能操作详情与位置按钮。失败和等待状态不应因折叠而消失。
- 检查输入摘要与详情的截断提示，长输出不能被显示成完整内容。回放旧 plugin records，确认仍可阅读，恢复过程不重复卡片或重复计费。
- 使用 `node --import tsx scripts/smoke.mts <agent-command> [args...]` 运行诊断：默认仅握手/会话能力检查，不发送 prompt。报告核对协议版本、Agent 信息、声明能力、配置与模式；缺失能力不是故障。只有显式追加 `-- '测试提示词'` 才会发送 prompt。
- 诊断报告的 `commands: null` 表示快照时尚未收到命令通知；`commands: []` 才表示 Agent 明确报告空列表。命令可能在创建会话后异步到达，不能把前者写成“不支持命令”。
- 若要验证真实 prompt，必须显式使用该脚本的 prompt 参数，并只在测试目录进行。检查退出后子进程和临时目录已清理。

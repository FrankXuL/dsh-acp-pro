# 03: 影子替换模型选择器的契约与实现骨架

Type: research

Status: resolved
## Question

在 DSH 0.2 里用 `priority` 更低的方式影子掉 `conversation.input.model`，自绘一个带左侧来源 tab（DSH / 每个 ACP）的模型选择器：确切的契约、数据来源、动作路径、行为面与实现骨架是什么？

先复用 [`docs/design/dsh-model-picker-research-2026-10-27.md`](../../../../design/dsh-model-picker-research-2026-10-27.md)（已有结论：选择器内部无来源 tab 插槽；`/model` 不读 label slot；低 priority 可影子 `single` 座位）。**它不够用的原因**：只证明了“可以影子”，没有回答“影子之后怎么把原生选择器的行为做对”。

需要回答（每条给源码契约 file:line，rc.3 打包件 + rc.2 checkout 双复核）：

1. 影子注册的规则与失败模式：同 priority 抛错、最低 priority 渲染、宿主未声明 slot / 0.1 核心时的装载失败表现。
2. 座位 owner props（`locked`）与作用域（`session`）语义；被寻址 subagent 会话、会话未就绪时怎么办。
3. 数据从哪来：`ctx.remote.session.modelCatalog()` 的完整 DTO（groups/failures/routableProviders/default）；当前选中的 provider/model 从哪读；effort 当前值与可选项从哪读。
4. 动作怎么发：选模型（`session.selectModel`? config option?）、选 effort、Agent 主动 `config_option_update`、失败/拒绝/回滚的确认链路；pending 态如何表达。
5. 原生座位的完整行为清单，逐项确认自绘必须复刻哪些：搜索（>4 模型）、前缀/对齐排序、键盘导航/焦点、勾选态、禁用/失败行、Effort 行、`conversation.input.model.label` 内联扩展（影子后是否还存在）、无障碍文案。
6. 刷新链路：`llm/adapters-updated`、`settings/document-updated`、凭据事件分别触发什么；影子组件要订阅哪些。
7. 两个入口的差异：`/model` 弹窗、设置页「模型」、当前会话面板在影子后各自保持什么行为；是否会在同一会话出现两个“当前模型”显示源。
8. 降级与可测试性：注册失败/接口缺失时如何回退原生座位；本仓 client 测试（happy-dom + stubs）能覆盖到哪一层；真机验收需要哪些步骤。

## Answer

已由 /research 子代理完成，新笔记：[`docs/design/model-picker-shadow-contract-2026-10-27.md`](../../../docs/design/model-picker-shadow-contract-2026-10-27.md)（调研笔记已于 2026-10-28 归档清理时删除）（rc.2 源码 + rc.3 打包件逐条复核；GUI 行为全部 `未实测`）。

**关键结论**
- 座位 `conversation.input.model` 由 `ui-conversation` 声明，`ui-model-selection` 只是注册者；影子必须用 `slots.inject` + `priority: -1` + 不声明子插槽；座位未声明时静默不生效（不是装载失败）。
- 数据面复用每会话唯一的 `modelDirectories.directoryFor(sessionId)`（与 `/model` 同一实例）；当前模型权威是会话投影 `modelSelection`；动作只有 `session/selectModel`，无乐观回滚，失败 toast 且菜单不关。
- **影子会让 `conversation.input.model.label` 失效**：第三方徽标静默消失（子插槽不能重复声明）。
- 降级三条：座位未声明（静默）、注册抛错（try/catch → 原生）、渲染崩溃（abdicate → 原生一次性）。
- 0.1 核心整体不 apply；`locked` 只禁 trigger；严格 session 座位保证有会话；被寻址 subagent 会话不渲染。
- 风险：影子是引擎行为而非文档化扩展点，DSH 升级风险高于普通注册；键盘/门户定位是主要工作量。

**待用户拍板（已转 #02/#05）**：是否接受 label 徽标失效；非 ACP provider 落点；影子是否作为默认形态、是否需要总开关。

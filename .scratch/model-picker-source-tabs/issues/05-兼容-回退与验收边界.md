## Question

影子替换方案能走多远、坏的时候怎么退？拍板兼容与验收边界。

（前置：影子替换契约研究票。）

需要拍板：

1. 目标宿主版本：只保证 0.2 核心（0.2.1-rc.3）还是兼顾 0.1；0.1 核心没有该 slot / 行为不同时怎么办。
2. 注册与运行期失败：slot 未声明、同 priority 冲突、渲染抛错、DSH 升级后 slot 改名——降级到原生选择器还是显式报错；是否需要配置开关强制原生。
3. 双入口不一致的产品口径：README / 设置页是否需要说明；是否在 `/model` 入口加提示（不能注入，只能文档）。
4. 测试与验收入口：单测覆盖到哪层（stubs 的影子注册 / 键盘 / 选择动作）、真实 DSH 验收清单（启用/停用、切 tab、切模型、/model、刷新、重启、权限/锁定）。
5. DSH 升级后的兼容复核触发条件与记录位置（沿用 `docs/dsh-plugin-dev/09-compatibility.md` 的证据格式）。
